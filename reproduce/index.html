    Reproducing the paper¶

    One command downloads the public data, runs the whole analysis, compares every table with the one kept in the repository and checks every number of the paper against the new tables.

    python -m flinch reproduce

    It needs 340 MB of downloads and about ten minutes. It leaves the spectra out, which are 143 GB; the levels below say how to include them. Nothing in the repository is modified. The new tables, the figures, the output of every step and a report go to reproduction/.

    Since 24 November 2026

    NOAA has reissued the GOES files, so a download made now is no longer the one of the paper. The command still finds the 255 numbers of the paper in agreement, but it reports two inputs as different and five tables as DIFFERENT, and its last line is Not fully reproduced. The reissue of the GOES files says what changed and how to get the tables of the paper exactly.

    From zero¶

    git clone https://github.com/gabgarar/flinch.git
cd flinch
python -m venv venv
venv/Scripts/python -m pip install -r requirements-lock.txt     # the exact versions used
venv/Scripts/python -m pip install --no-deps -e .
venv/Scripts/python -m flinch reproduce

    On Linux and macOS the interpreter is venv/bin/python. The paper was computed with Python 3.14 on Windows 11. Without the first pip line, pip install -e ".[analysis,dev]" installs the current versions instead, which is fine for using the package but is not the same test.

    Four levels¶

    Each level adds a download to the one before.

    Level Command Download Time What it shows
    0 python -m flinch verify none seconds The numbers of the paper are those of the tables in the repository
    1 python -m flinch reproduce 340 MB 10 min The public archives and this code give the 14 velocity tables again
    2 python -m flinch reproduce --spectra sample 1.1 GB more 5 min more Ten spectra of the paper, drawn at random, are still the same in the archive
    3 python -m flinch reproduce --spectra all 143 GB more 3 hours or more The spectral tables too: Tables 2 and B.1 and Fig. 4 of the paper

    --sample 30 changes the number of spectra of level 2. --no-download uses the data already on disk. --out names another folder for the output. A run that is stopped can be started again, and what is on disk is not downloaded twice.

    The report¶

    reproduction/report.txt has six parts.

    1. Data. Each input is compared with the one used in the paper by a fingerprint (SHA-256) of what the analysis reads from it. identical means that the archive still serves the same data.
    2. Velocity analysis. One line per command, with the time it took and the file that keeps its output.
    3. Spectra. How many extracts are identical to those of the paper, and whether the spectral analysis was repeated.
    4. Figures. The figures of the paper, as PDF, in reproduction/figures/.
    5. Tables. Each new table against the one in the repository. identical is the same text. same numbers means that every number agrees to nine significant digits, which is what another processor or another version of a library can change. The response of the spectra is written in parts per thousand or per million of each quantity, and there the nine digits are those of the quantity. DIFFERENT names the columns that differ and by how much.
    6. Numbers of the paper. The 255 numbers of the text and the tables of the paper, each against the new tables. A number passes when the paper gives a correct rounding of it.

    The last line is Reproduced. when no step failed, no table differs and every number agrees. The command then ends with code 0, and with 1 otherwise.

    results/paper_check.csv lists the 255 numbers with the place where each appears in the paper, as the last run of verify left them.

    What was run for the paper¶

    On 21 and 22 November 2026 everything was downloaded again into an empty folder and run from a fresh clone, with the versions of requirements-lock.txt.

    What Result
    Inputs of the velocity analysis (12 files) identical, 12 of 12
    Velocity tables (14) identical, byte for byte
    Spectra (1296 files, 143 GB) identical, 1296 of 1296
    Spectral tables (2) identical, byte for byte
    Numbers of the paper (243) 243 of 243 in agreement
    Figures of the paper (5) the same images, pixel by pixel

    The check found two numbers that had been rounded twice in the text. The scatter of the velocity changes of the HARPS-N flares is 0.40 m/s, not 0.41, and the excess of Appendix C is 0.43 ± 0.10 m/s, not 0.44 ± 0.11. Both are corrected.

    On 22 November 2026 it was run on Linux in two ways. The reproduce workflow of the repository ran it on GitHub from the public archives, with ten spectra of the sample, in six minutes. The 12 inputs and the ten extracts are identical. On Ubuntu 24.04 with Python 3.12 the whole analysis, the spectral part included, was run on the 1296 extracts. In both, the 243 numbers agree and every table has the same numbers. The largest difference is in the eleventh significant digit. The five figures drawn on Linux are the same images as those of the paper.

    The run on Linux found one defect, now corrected. The depth and the width of the mean line come from an iterative fit, which stopped within a few hundredths of a part per million of its minimum, at a point that depended on the machine. The two machines differed by up to 0.0001 ppm in those two columns of spectral_response.csv, and the command reported the table as DIFFERENT. The fit is now carried to convergence, and the two machines agree to the last digits that the arithmetic keeps. The change moved those two columns by less than 0.0001 ppm, against errors of 50 to 80 ppm, so spectral_response.csv is no longer byte for byte the table of the first run. No number of the paper and no figure changed. Run again on Windows with the corrected fit, the 16 tables are identical to those of the repository. The spectra were not downloaded a second time, because the extracts are the same files.

    On 23 November 2026 a last review of the paper added twelve numbers, and the command now checks 255. They are the measurement without the flares that start soon after another one (four new rows in cleaning_variants.csv), the number of controls of a flare, and what the paper derives from the brightening of flares in visible light. The same review made the probability of detecting a shift use the shift as it is measured back, as the injections of NEID already did, and that number of the paper went from 99 to 98 %. Run again on Windows with the data on disk, the 16 tables are identical to those of the repository and the 255 numbers agree.

    On 24 November 2026, the day the paper was submitted, version 1.0.0 was checked as it is archived at Zenodo. The archive is identical, file by file, to the tag of the repository. Installed from it in an empty folder, the 122 tests pass and the 255 numbers agree. On Ubuntu 24.04 with Python 3.12 the whole analysis on the data of the paper, the spectral part included, ends with Reproduced. and every table has the same numbers. On Windows, with the frozen copy of the data, the 16 tables are identical to those of the repository. A download from the public archives made that day no longer gave the inputs of the paper, because NOAA had reissued the GOES files. The reissue of the GOES files describes it.

    Step by step¶

    reproduce runs these commands in this order. Each can be run alone, and then it writes to results/.

    python -m flinch download
python -m flinch coverage
python -m flinch replication
python -m flinch replication --cleaning
python -m flinch robustness
python -m flinch pilot
python -m flinch numbers
python -m flinch paper-spectra
python -m flinch chromosphere
python -m flinch paper-figures --out figures
python -m flinch verify
    Output Made by Content
    results/flare_sample.csv coverage The 2122 M and X flares and their coverage by NEID
    results/velocity_by_instrument.csv replication Mean change, shift of an X1 flare and rotation term, by class and instrument, and both together (Table 1)
    results/replication_events.csv replication Every flare and control of both instruments, with its velocity change (Fig. 3)
    results/replication_profiles.csv replication Mean velocity around the peak in 10-minute bins (Fig. 2)
    results/early_window.csv replication Mean velocity from 60 to 50 minutes before the peak, by class and instrument (Appendix C)
    results/cleaning_variants.csv replication --cleaning The mean change and the rotation term with other thresholds for dropping days and, for HARPS-N, with the quality flag above 0.9
    results/robustness.csv robustness The table of variants with NEID (Table A.1)
    results/injections.csv robustness A shift added and measured back with NEID (Appendix A)
    results/pilot_*.csv pilot The first NEID analysis, including the oscillation power
    results/text_numbers.csv numbers The counts and descriptive numbers of the text: velocities and days, what the cuts remove, the tests of a fair sample, the flare rate and the time in flare
    data/spectra/ paper-spectra The extracts of the 1296 spectra of the paper, each checked against its fingerprint
    results/spectral_response.csv chromosphere Response of every flare and control, with its errors (Table B.1)
    results/spectral_indices.csv chromosphere Summary of each index by class band (Table 2)
    PDF files paper-figures The example of the method, the mean velocity around the peak, the change of each flare against class and position, and the mean response of the spectra
    results/paper_check.csv verify Every number of the paper against the tables

    Three environment variables move things. FLINCH_DATA is the folder of the downloads (data/ by default), FLINCH_RESULTS that of the tables (results/), and FLINCH_DATA_END the last day of data (see below).

    What is fixed, and how¶

    Four things made the results depend on the day and on the machine. They are now fixed in the code.

    • The last day of data. The NEID table grows every clear day and the GOES lists are reissued with a later end date, so a later download had more flares, more observations and other controls. DATA_END in flinch/config.py is 13 November 2026. Flares and observations from that day on are ignored, whatever the download holds. The last NEID observation of the paper is of 12 November 2026.
    • The spectra. They were fetched with campaign, which works through the flares from the strongest down until a budget of hours and files runs out. What it fetches depends on the connection and on the day. flinch/reference/spectra_files.csv lists the 1296 files that it fetched for the paper, with the fingerprint of each extract, and paper-spectra fetches exactly those.
    • The random choices. Controls and bootstrap use a fixed seed.
    • The numbers of the text. Counts, percentages and tests that were not in any table are now written by numbers.

    Limits¶

    What follows can still make a reproduction differ, or makes it expensive.

    • The archives can change the data. NEID can reprocess its spectra with a newer pipeline (the 1296 used here are all of version 1.5.3), and NOAA reissues the GOES files, as it did in November 2026. The fingerprints do not prevent a change, but they detect it. The report then says which input is different, and a table that differs has an explanation. A frozen copy of the GOES files, of the NEID table and of the extracts of the 1296 spectra, as they were when the paper was computed, is attached to release 1.0.0 of the repository (flinch-data.zip, 556 MB). The reissue of the GOES files says how to repeat the paper with it, without the 143 GB.
    • The spectra are 143 GB. A level-2 file is 113 MB and the archive does not serve parts of a file, so each one is downloaded whole, reduced to an extract of 0.2 MB and deleted. The 1296 files took 3 hours and 14 minutes here, at 12 MB per second, which is 9 seconds per file. A slower line needs more in proportion. They need 400 MB of free disk at a time and leave 260 MB of extracts. A home connection may slow down after tens of GB. In the first campaign it fell to a tenth of its speed after 100 GB. In this second download it did not. The computer must stay awake, so a laptop should be plugged in and should not sleep when the lid closes. Level 2 is the cheap alternative. It does not repeat the spectral analysis, but it shows that the archive and the extraction still give the same extracts.
    • Some spectra cannot be read. For 51 exposures of two windows (27 of the X1.3 flare of 4 July 2026 and 24 of the control of the X4.9 flare of 31 December 2023) the archive serves files without the stitched spectrum. They are not in the list, and those two windows have fewer spectra than the others. That flare and that control are not among the usable ones.
    • The choice of the spectra is not repeated. The list records which spectra were fetched, not a rule that gives them again. The windows are the 20 X-class flares that NEID observed at the peak or during the rise, the same hours on the nearest flare-free day for 14 of them, and the 11 of the 25 flares between M5 and M9 that had a steady clear sky. Within a window, every spectrum near the flare was taken and one in two or three farther away. Running campaign again would not give the same files, because its budget cut the last window short and the two windows above lost spectra.
    • Software versions and machines. With the versions of requirements-lock.txt on Windows 11 the tables come out identical, byte by byte. On Linux the same versions give the same numbers to eleven significant digits, but not the same text, because another processor and other mathematical libraries round the last digits differently. Tables are therefore compared number by number, not only as text, and the report says same numbers. On Linux the extraction was checked on ten spectra taken from the archive, and the spectral analysis on the 1296 extracts made on Windows. The download of the 143 GB has not been repeated there. macOS has not been tried. NumPy does not promise the same random numbers in every future version. If they changed, the controls drawn and the bootstrap errors would change in their last digits.
    • Figures are not compared by the command. They are drawn again from the new tables. For the runs described above, on Windows and on Linux, they were turned into images and compared with those of the paper, and the five are the same pixel by pixel. With other versions of Matplotlib or other fonts they can differ in details that do not change what they show.
    • Numbers taken from other papers (the brightening of two flares in visible light and the factor of the old GOES scale) are written in flinch/verify.py as they were read in those papers. What the paper derives from them is checked. The papers themselves are not read by the command.

    The reissue of the GOES files¶

    Between 22 and 24 November 2026 NOAA reissued the GOES files that the paper uses. The download of 21 and 22 November still gave the files of the paper. A download made since then does not.

    Four things changed, up to the last day of data of the paper.

    • The list of flares is the same. It has the same 2187 flares of class M and X, with the same times and classes.
    • The heliographic longitude and latitude of the flares moved by 180 degrees, in about 1960 of them. In the earlier files most latitudes lay outside the range from −90 to 90 degrees, and in the reissued files none does, so the earlier values were wrong. The analysis does not depend on them. It uses the position on the disc, the Carrington longitude and differences of latitude. The columns lon and lat of results/flare_sample.csv and results/pilot_flares.csv come from the earlier files and should not be used as heliographic coordinates.
    • The one-minute X-ray fluxes of GOES-18 between 9 October and 11 November 2026 changed by up to 14 %.
    • The peak flux and the fluence of about a dozen flares changed by a few parts in a million.

    This is what python -m flinch reproduce reports with a download of 24 November 2026.

    What Result
    Inputs of the velocity analysis (12 files) 10 identical. The GOES list of M and X flares and the GOES-18 one-minute fluxes of 2026 are different
    Velocity tables (14) 9 identical or with the same numbers. 5 are DIFFERENT
    Numbers of the paper (255) 255 of 255 in agreement
    Figures of the velocity analysis (3) the same images, pixel by pixel
    Last line Not fully reproduced, and the command ends with code 1

    Of the five tables that differ, flare_sample.csv and pilot_flares.csv do so in the columns lon and lat and, by less than one part in 100 000, in the fluence and the position of a few flares. velocity_by_instrument.csv and robustness.csv differ by 0.000000002 m/s at most, in the rotation term and in the shift of an X1 flare, and pilot_tests.csv by as little in one test statistic.

    To get the tables of the paper exactly, use the frozen copy. Unpack flinch-data.zip in the folder of the code, which gives data/. Then fetch the HARPS-N series alone, which is a fixed release with a DOI and is not copied, and run the analysis on what is on disk.

    python -c "from flinch import harpsn; harpsn.download_series()"
python -m flinch reproduce --no-download --spectra all

    Do not run python -m flinch download in that folder. Since the reissue it also fetches the new flare lists of GOES-18, whose file names carry a later end date, and the code reads the latest list that it finds in data/goes/. Earlier versions of this page recommended that command. Run as above on 24 November 2026, with version 1.0.0 as archived at Zenodo, the 16 tables are identical to those of the repository and the last line is Reproduced.

    Tests¶

    python -m pytest              # 122 tests on synthetic data, no network, one minute
python -m pytest -m network   # 2 tests: the archives still answer as the code expects

    Three more tests compare the real downloads with the tables of the repository. They run when the data are on disk.
